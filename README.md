# 稳拷 steadcopy

**插卡自动备份、双端校验、拷完给一张人话报告。**

面向中文创作者与小团队的 Windows 拷卡（DIT offload）工具。开源、MIT、**长期免费且含商用**。

---

## 为什么又做一个

免费界不缺校验能力，也不缺正确架构——缺的是**把这几件事装进同一个面向创作者的、真免费的壳里**。既有方案各断一条腿：

| 方案 | 断在哪 |
|---|---|
| DaVinci Resolve 的 Clone Tool | 架构完全合格，但困在数 GB 的 NLE 与 DIT 术语里；校验遍慢到被官方论坛长期抱怨；写 MHL 但**不能复验** |
| TeraCopy | 校验能力强，但**多目的地与报告导出恰好锁在 Pro**，免费版不含商用 |
| FastCopy | 引擎快，但单目的地，免费版不含商用 |
| FreeFileSync | 同步定位错配，校验开关藏在配置文件里且作者自认实现存疑 |
| rclone / robocopy | 人群不对；robocopy 根本无内容校验 |
| Hedge → OffShoot | 2023 年改名时**撤销了免费档**，空位至今无人补 |

稳拷要补的就是这个空位。它不承担营收，所以：**零账号、零付费墙、零服务端依赖、离线可用、零遥测。**

## 现在能做什么

- **整卡镜像**为默认。只排系统垃圾，看不懂的文件照拷——配套文件缺一个就可能让整条素材在剪辑软件里废掉（Canon 的 `INDEX.MIF`、Insta360 的双 `.insv`）
- **单遍读源、多目的地并行写**（1–4 个）。源只读一遍，数据同时喂给全部目的地与哈希器
- **边读边算 XXH64**，零额外读源；可选 MD5
- **无缓冲读回校验**（`FILE_FLAG_NO_BUFFERING`）。不绕过页缓存的「校验」读到的可能是内存副本，介质写坏完全测不出来——那比不校验更危险
- **校验失败自动重拷**，重试集合逐轮收窄、指数退避
- **断点续传**。账本作用域是「目的地 × 源卡」，判定已完成要三件事同时成立：清单有记录、当初校验通过、目的地上文件现在确实还在
- **一键复验四态**：一致 / 已移动 / 丢失 / 新增。不压缩成布尔结论——你想知道的是「**哪些**文件出了**什么**问题」
- **中文人话报告**：单文件 HTML，样式内联、可离线打开、可打印成 PDF，应用内直接查看
- **凭证随数据走**：清单落在目的地目录内，整个目录搬走凭证跟着走
- **源卡只读**：绝不向源设备写入任何东西，包括设备标记

## 下载与校验

从 [GitHub Releases](https://github.com/steadcopy/steadcopy/releases) 或官网下载。

> **本版本未购买代码签名证书**，首次运行 Windows 会提示「未知发布者」。这是预期行为。
> 请按下面的方法核对校验码来确认来源。**任何时候都不要为了运行本程序去关闭系统防护或杀毒软件。**

核对方法（PowerShell）：

```powershell
Get-FileHash .\稳拷_0.1.0_x64-setup.exe -Algorithm SHA256
```

把结果与 Releases 页面公示的值逐字比对，一致才安装。

安装包约 200 MB，因为**把 WebView2 运行时完整打进去了**——片场没网是硬约束，安装时不该再去联网下载组件。

## 命令行

引擎与界面共用同一套 core，命令行是一等公民（也是端到端测试的驱动面）：

```bash
steadcopy devices                                    # 列出本机卷，标注哪些可作为源
steadcopy scan E:\ --list                            # 扫描源
steadcopy plan E:\ -d D:\素材 -d F:\备份 -p 婚礼      # 预演，零副作用
steadcopy copy E:\ -d D:\素材 -d F:\备份 -p 婚礼      # 执行
steadcopy audit <清单.json>                          # 复验，四态结果
steadcopy report <清单.json>                         # 由清单生成报告
```

每个命令都支持 `--json`（stdout 只出 JSON，日志走 stderr）。退出码：`0` 成功 / `1` 终态族 / `2` 可重试族 / `3` 取消 / `4` 用法错误。「无新素材」是正常结果，退出码是 `0`。

## 从源码构建

```bash
cargo test              # 引擎与命令行（安全轨，零副作用）
cargo build --release   # 命令行
cd app && bun install && bunx tauri build   # 桌面应用与安装包
```

需要 Rust 1.96+、Bun、以及 Windows 的 MSVC 生成工具。

## 已知边界

- **仅 Windows**。核心是平台无关的，mac 的位置留着了，但没做。
- **手机走 MTP，做不到可信备份**。安卓与 iPhone 在 Windows 上是「便携设备」，没有盘符也不是文件系统对象：没有块级校验、文件大小可能被 32 位截断、时间戳不可信、≥4 GB 高危。目前建议手机用 SD 卡或外置 SSD，相机用读卡器。
- **iPhone 默认会把 HEIC/HEVC 转码成 JPEG/H.264 再传给电脑**（设置 → 应用 → 照片 → 传输到 Mac 或 PC）。转码发生在手机端，任何拷贝路径都逃不掉——**默认设置下你拿到的不是原文件**。要备份原片请先改成「保留原始格式」。
- 格式化、插卡自动检测、任务台账数据库尚未完成，见 `openspec/changes/`。

设备接入方式的完整调研见 [`docs/source-devices.md`](docs/source-devices.md)。

## 工作制度

本仓遵守三套制度，正本在 [`openspec/README.md`](openspec/README.md)：

- **SDD**：OpenSpec，禁 propose→apply 一把梭，人审是不可跳过的闸门
- **TDD**：规格锚定的 Detroit 式——每条 spec 场景对应一个同名测试；不 mock 文件系统，用真实临时目录 IO；对抗测试是一等公民
- **双轨约束**：会格式化、需管理员、碰物理设备的测试进危险轨，三重闸门且**不在开发机执行**，登记在 [`docs/danger-tests.md`](docs/danger-tests.md)
